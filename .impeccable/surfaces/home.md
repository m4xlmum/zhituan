# 首页（起始页）

## Scope

`src/renderer/home.html` 与 `src/renderer/src/home/`（`HomeApp.vue` 数据与动作、
`StartPage.vue` 骨架与排版、`useRows.ts` 行与交互、`useTiles.ts` 站点编排、
`ThemeMenu.vue` 主题菜单），以及它依赖的两份共享声明：`src/shared/constants.ts` 的
`SECTIONS`（栏目表）与 `src/shared/presets.ts` 的 `section`（域名归属）。
配色与形状的**值**只有一份，在 `src/renderer/src/styles/themes.css`。

窗口默认 960×540 的 16:9 横屏。起始页**不占整扇窗**：界面层只画顶栏与右侧栏
（44px 高、48px 宽，`@shared/constants`），这一页被摆在它们让出来的那个矩形里
（`windowController.getBodyRect()` → `geometry.ts` 的 `computeLayout().body`）。
因此它的视口是算出来的，不是窗口尺寸：

| 状态 | 窗口 | 正文区（这一页的视口） |
|---|---|---|
| 默认（地址栏折叠） | 960×540 | **912×496** |
| 地址栏展开 | 960×540 | 912×462 |
| 最小档（预设 mini） | 480×270 | **432×226** |

这四个数只有一份来源，就是 `computeLayout` 本身；`spike/preview.js --body` 把
`constants.ts` 与 `geometry.ts` 打成一包再 require，用的正是应用那个函数——
因此这里写下的数字与探针量到的不会是两份。按整扇窗渲染出来的图比真机宽 48、
高 44，而高度恰是最紧的那一轴，于是「放得下几行」会被量多一行。

## Visitor mode

**Operate。** 用户来这里是为了尽快开始读，不是为了被说服。界面的成功标准是他能在
一秒内认出「这是在工作」，并在两秒内打开想读的东西。

## Audience, job, action

- **受众**：办公室 Windows 用户，屏幕随时可能被看到（走过来的同事，或正在进行的屏幕共享）。
- **任务**：在不离开工作界面的前提下开始阅读——网页的，或本机的。
- **动作**：换一个板块（视频 / 阅读 / 资讯 / 刷题 / 离线阅读 / 全部）、打开某个站点、
  继续上次的阅读、打开本机的一本书、搜索。
- **内容**：站点来自「我的站点」、常访问与内置热门站点（`src/shared/presets.ts`）；
  本机文件来自浏览历史里 `file:` 的那些条目。全部为真实数据，不虚构任何统计或评价。

## Constraints

- chrome 层覆盖整个窗口，正文区**必须可透明**：窗口透明时用户看到的是桌面，不是我们的背景色。
- **禁止毛玻璃**：`backdrop-filter` 在透明窗口背后模糊不了桌面，只能模糊自身内容。
- **扫描线那一层不许进 chrome**（`styles/home.css` 里 `html[data-world='terminal'] body::after`）：
  它是铺满视口的覆盖层，进了 chrome 就把桌面盖住，而这个产品赖以存在的机制当场就没了。
- 正文区高度只有 496px（地址栏展开 462，迷你档 226），16:9 下宽度充足、高度紧张——
  横向组织优先，**不做长滚动**：一屏放得下的行才渲染，长尾靠输入框过滤。
  实测的行数预算（`spike/preview.js --body` 量出来的行数，不是算出来的）：
  纸白与暗夜在默认档 11 行、地址栏展开 10 行、迷你档 3 行；磷绿的行距更紧
  （默认 22px 对 28px），默认档 **14 行**、迷你档 4 行。加了格式说明的「离线阅读」
  那一栏少一行（说明条自己占掉 6px + 一行 18px，默认档剩下 3 行）。
- 界面语言为简体中文。正文与关键标签不小于 12px（迷你档降到 11px，缩的是栏目线里非当前的那几栏）。
- 透明度会常态处于 25%–45%，因此**关键控件的可辨识不能只靠颜色**，需要形状或位置上的区分。
- **本机路径不出现在任何一屏上，包括不可见的地方**：`file:` 的条目只显示文件名
  （`@shared/url.ts` 的 `fileNameOf`），而且那条行**不挂 `:title`**——行上的字是干净的、
  悬停时浏览器却把整条 `file:///C:/Users/…/书.txt` 弹在屏幕上，这是上一轮被评审抓到的
  漏法。规矩因此写成一条：本机文件的行既不在文字上带路径，也不在任何属性上带路径；
  探针里 `pathLeaks`（文字）与 `titleLeaks`（属性）各问一遍，两条都必须为空。
  这个程序的全部意义是别人看不出你在干什么，而 `C:\Users\…\Documents\…` 把用户名和
  目录习惯一起摊在屏幕上。

## Chosen direction

**报纸的栏目页。** 顶上一条栏目线（全部 / 视频 / 阅读 / 资讯 / 刷题 / 离线阅读），
当前那一栏的字比其余大一个数量级（26px 对 12px），底下压一根 2px 强调色短线，
其余各栏吊在同一条基线上；栏目线下面是一根细线，再下面按栏目排条目。
行是横向的：动词 · 图标 · 名称 · 右端域名。

**它拒绝的类别默认**：图标磁贴墙 + 大号欢迎语（「Welcome back!」式的问候 + 等距圆角磁贴
+ 悬停上浮）。理由是这台机器上的真实动作是**分类**——今天摸哪条鱼：看视频、读小说、
刷题、还是读本机的那本书——而磁贴墙把 20 个入口平铺在一起，把分类这件事留给用户每次
自己重做一遍。

**它也不做**：卡片、阴影、色块导航、装饰性插图。栏目的划分取自墨鱼阅读的使用指南
（网页 / TXT·PDF 离线），因此「离线阅读」是一个真有内容的板块，不是占位。

**Memorable moment**：按下「打开文件…」，系统选文件框选中一本 TXT，一张标签页直接打开
它——没有书架要维护，没有导入要等待。

**它唯一被安排过的那一下**：换一栏。栏目线与底下那一列是同一个动作的两半，因此同一个
时长、同一条缓动——底下那一列从**已经看得见**的 0.55 落定（`settle`，透明度 + 4px 上浮），
当前栏那根 2px 强调色短线同时从左边画出来（`rule-in`，`transform-origin: left`）。
两条都是 180ms `cubic-bezier(0.16, 1, 0.3, 1)`，一次就完，没有第二处动效。
打字过滤**不重放**它：那是同一个动作的延续，不是新的一栏（`columnKey` 只看栏目与
「在不在搜索」，不看输入框里那几个字）。`prefers-reduced-motion: reduce` 下三条
（这一对加方块光标的闪烁）一起撤掉——撤掉的是动画，不是结果：换栏仍然是换了一栏，
只是当场换完。

**它只在真的换了一栏时播**：两条动画都挂在 `.settle` 上，而那个类要等 `columnKey`
变过一次才有。页面刚出现时那一列已经在它该在的位置上，让它从 0.55 落定下来，
说的是一件没发生过的事。这一条是收尾评审抓出来的回归——此前动画无条件挂在 `.rows`
上，首帧也走一遍，而取证那一跑从没换过栏，量到的其实是挂载那一次；「换栏会动」
因此从来没有被真的验过，被验的只是「有这么一条动画」。现在拆成三跑分开问：不换栏
（无）、换栏（两条 180ms 同一条曲线）、减少动态下换栏（无，但栏目确实换了）。

**进来就有光标**：这一页的键盘整副挂在输入行上——`onInputKeydown` 是它唯一的 keydown，
← → 换板块、↑ ↓ 选行、↵ 开当前行都在里面——所以「没有元素被选中」等于「一个键都不响应」，
而状态行第一帧就写着「← → 换板块」。挂载时给一次焦点，窗口重新获得焦点时再给一次
（后者管的是从网页切回这一页）。探针直接问 `document.activeElement`，该是 `input`；
不能靠截图判——那道下划线的颜色变化太小，认不出来。

**展示字**：报头（`纸团`）与栏目线整条用的是**自带的一份衬线**，不是平台字体。
它是这一页的门面，用别人机器上的默认脸就等于这一页在谁的机器上就长成谁的界面。
来源是 Noto Serif SC（OFL 1.1，无保留字体名），由 `scripts/make-display-font.mjs`
从真实用到的字符集子集出来（27,548 B 的 woff2，随源码一起进仓库，`OFL.txt` 同目录）。
CSP 里没有 `font-src`，于是它落在 `default-src 'self'` 下——这也是必须自带的第二个理由：
远程字体当场就被挡掉。终端世界的展示字**就是它那套等宽字**（`--font-display: var(--font)`），
命令行里没有第二个字面。

**Build path**：code-led（本会话没有图像生成工具，不产 comp；方向契约下面的
FIRST VIEWPORT 与「打开文件」这个签名动作由收尾评审按行为审）。

## Direction contract

**THESIS** — 起始页是一张报纸的栏目页，不是一面图标墙。它拥有的一件事是**分类**：
页面的主角是「栏目」这个动作，站点只是每个栏目底下的条目。它拒绝的是把入口平铺成
等距磁贴、再配一句欢迎语——那需要用户每次自己重新分类。

**OWN-WORLD** — 纸/靛两级墨加一个强调色：纸白 `#f9fafb` 冷白纸、`#15181d` ink、
`#5a6270` dim、`#2f4a9e` 靛强调，细线 `#e6e8ec` / `#d2d6dd` 分节；暗夜与磷绿是同一套
结构的暗色形态。**零卡片、零阴影**，层级全部由字号、字重与那 2px 短线承担。
报头与栏目线整条用的是**自带的一份中文衬线**（`Zhituan Display Serif`，27KB 子集，
见「展示字」一段），终端世界里它换成那一套等宽字。
组件语汇：栏目线（26px 当前栏 + 12px 其余 + 2px 强调色短线）、下划线输入行、
28px 行高的横向条目（动词列 · 18px 图标格 · 名称 · 右端域名）、底部状态行
（读数在左、主题键在右）。把所有文字拿掉之后，剩下的应该是栏目线、一根细线与一列对齐的条目。

**STORY** — 用户打开就落在「全部」上，一眼看见继续上次的那一条与所有站点；用 `←` `→`
或直接点换一栏，底下换成那一栏的东西；`↵` 开当前行；右下角把主题从纸白换成暗夜或磷绿；
切到「离线阅读」时，那里有一行「打开文件…」，按下去就能把本机的一本书读起来。

**FIRST VIEWPORT** — 自上而下五段：页眉（标识 + `标签 6`）→ 下划线的输入行 →
栏目线（当前栏 26px ink + 2px 靛短线，其余 12px dim，共用一条基线）→ 内容行
（28px 行高，第一行是「继续 番茄小说 · 第一二八章」这样的继续上次）→ 状态行
（左端 `站点 16`，右端主题键 `主题 · 纸白`）。迷你档（432×226）整组降一档：
栏目线缩到 18px/11px，六栏放不下时退成两字缩写（`离线阅读` → `离线`），
状态行藏掉按键提示。

**FORM** — 报纸的刊头与栏目线（分类页），不是磁贴网格。这一轮由用户在四个方向问题上
直接指定（顶部板块条 / 真能打开本地文件 / 结构新观感仍克制 / 按新起始页重做整套主题），
**没有走发牌那一步，因此没有种子键**；上一次的 `784114e2`（机读答题卡）属于已废弃的那一版。

**FINISH** — unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance.

## Unresolved

- 「打开文件…」后系统选文件框里的过滤器只有 TXT / PDF 一组，**不挂「所有文件」**：
  列上它之后用户能选中一本 EPUB，然后看着它变成一次下载，那比选不到更让人摸不着头脑。
  EPUB / MOBI / AZW3 仍在路线图里未实现。
- 最短的那几栏（视频 6 条、刷题 3 条）在默认档会在列底下留出大片空白。这一处**已经
  设计过了**：整栏都渲染出来时（没有被上限截掉），列的最下面居中画一条 56×1px 的
  收尾线（`--divider-strong`）——报纸收尾画的就是这个。它说的是「就这些」，
  不是「还有，往下滚」，因此 `visible.length < limit`（真的到底了）才画，
  相等（正好铺满）或被截掉时都不画：被截掉时它就是在说谎，而这一页从不滚动。
  实测：视频 / 刷题 / 离线阅读在默认档有这条线（y=448 / 448 / 420），
  迷你档的刷题（3 行正好铺满）没有。
- 栏目线在更窄的窗宽下会不会挤到需要第三档字号，尚未实测。已知的是 432（最小档
  的正文区）那一档会退成两字缩写，四字栏名 `离线阅读` → `离线`；420 以下没有测试。
- 主题仍是三套（亮 1 暗 2）。架构上加一套就是加一段变量组加 `HOME_THEMES` 一行，随时可加，本轮不铺开。
- 「从网页切回这一页时光标会不会自己回来」这一半**没有在真机上验过**。它的依据是
  Chromium 里「一份文档只有被聚焦时它的 window 才收到 focus」，而探针只有一扇窗，
  跑不出多个 WebContentsView 并存的场景。真机上点一下「起始页」那颗键、直接按 ← →
  就知道了；不成立的话，退路是在主进程切到这一屏时叫一次 `webContents.focus()`。
- 主题菜单的浮层宽度写死 268px（原先 252），刚好放下最长的那条说明（17 字，11px）。
  再长一个字就又会折行，而它现在靠的是一个数而不是约束。
- 展示字只覆盖「这一页真的会说的那些字」：`scripts/make-display-font.mjs` 从
  `SECTIONS` 与 `StartPage.vue` 里抽出字集再子集，用户自己加的站点名与书名
  **不在**那份字集里，会落到 `--font-display` 后面的兜底衬线。这是有意的取舍
  （中文字体整份 25MB，子集之后 27KB），但没有为「落回兜底时好不好看」做过设计。
